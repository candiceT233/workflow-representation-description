# Research Formulation: ILP for HPC Workflow Deployment
*Inspired by Liu et al., OptiPIM (ISCA '25)*

### 1. The Decision Space (Variables)
To find the optimal deployment, we define the following variables:
* **Placement Variable ($P_{i,j}$)**: A binary variable where $P_{i,j} = 1$ if Task $i$ is deployed on Hardware Node $j$, and $0$ otherwise.
* **Parallelism Factor ($Par_i$)**: An integer variable representing the number of concurrent instances for Task $i$, capped by the physical constraints of the selected environment ($N_{max\_parallel}$).
* **Storage Mapping ($S_{i,k}$)**: A binary variable where $S_{i,k} = 1$ if Task $i$ is assigned to use Storage Tier $k$.

### 2. The Objective Function (Minimize Latency)
The goal is to minimize the total execution time ($Obj$) by summing the following performance factors:
* **$Cost_{compute}$**: Calculated as $\sum (InputSize_i / PerformanceProfile_{j})$ for all active nodes. This uses your benchmark records to estimate time based on hardware selections.
* **$Cost_{I/O}$**: Calculated as $\sum (DataVolume_i / Bandwidth_{k, pattern})$. This maps the workflow's I/O patterns (e.g., sequential vs. random) to the recorded bandwidth of the selected storage environment.
* **$Cost_{comm}$**: Represents the overhead of data movement between tasks. If $Task_i$ and $Task_{i+1}$ are placed on different nodes, this adds the network transfer latency to the total cost.

### 3. Constraints (Boundaries)
The Integer Linear Programming (ILP) solver must satisfy these hard boundaries:
* **Capacity Constraint**: The total data generated by the workflow must not exceed the physical limit of the assigned storage tier ($\sum DataVolume \le StorageCapacity_k$).
* **Throughput Constraint**: The aggregate I/O requests from parallel tasks must not exceed the maximum bandwidth capability of the storage environment for a specific access pattern.
* **Dependency Constraint**: A task cannot begin until its predecessors are complete and the necessary data has been transferred.

### 4. Strategic Insight: Pattern-Awareness
A key component of this formulation is treating **Data Locality** and **I/O Patterns** as primary drivers of the cost model. Rather than assuming a uniform transfer speed, the model uses your comprehensive benchmark profiles to select hardware and storage pairings that specifically match the I/O signature of each task.
